## Remote and SOCKS forwarding, one connection per host, and Claude's progress updates

New since 0.5.0:

- **A page for port forwarding**: **Port Forwarding** in the sidebar lists every host's rules, a section per host, where you add, edit, delete, start, and stop them. The host editor no longer has a forwarding section. **Start** works with nothing open on the host: it connects without a terminal and asks what a terminal tab would. A running rule shows its address to copy, a rule that fails to start shows why with **Retry**, and **Start on connect** starts a rule whenever the host connects. In a terminal tab, **Port Forwarding** in the status bar shows the host's rules, and **Manage Port Forwarding…** opens the page at the host.
- **Remote and SOCKS forwards**: besides local forwards (`ssh -L`), a rule can be remote (`ssh -R`), where a port on the server leads to an address this computer reaches, or dynamic (`ssh -D`), a SOCKS proxy on this computer whose connections the server makes. A remote rule listens on the server's `localhost` unless you choose another address.
- **Forwards in the background**: forwards keep running after you close their tab, with the window in the tray, and behind the lock screen unless **Disconnect all sessions when locked** is on. The tray menu lists them under **Port Forwarding**, each with **Stop**, and **Copy Address** when it listens on this computer. When a connection drops, its forwards stop and Hatoba says so: in the window when it's in front, otherwise in a system notification that opens the page. Nothing reconnects on its own.
- **One connection per host**: a host's terminal tabs and forwards share one SSH connection, and take over the dashboard's when it is connected to the host. New tabs open on it without signing in again, so a password set to **Ask Each Time** or a second factor isn't asked for each tab. The connection closes when its last tab and forward close. Quick connections still open a connection per tab.
- **Claude's progress updates**: Claude Fable 5, Mythos 5.1, Opus 5.5, Sonnet 5.5, and their later versions write updates for you between tool calls, which Hatoba used to fold into the collapsed **Reasoning** block. They now show in the reply, and an answer written before a last tool call, such as saving a memory, no longer reaches you as a one-sentence summary. Over the Anthropic protocol these models show **Thinking** while they think instead of a Reasoning block, and so do GPT models whose reasoning summary doesn't arrive. When a provider or gateway refuses this, Hatoba asks again the old way.
- **Sending a queued message now**: the queued message's card has a send button between **Edit** and ×. It stops the reply, like Stop or Esc, and sends the queued message.

Asked for a host's memories, the assistant no longer counts the global ones as the host's. Busy buttons keep their size, and live figures such as resource usage and download progress keep their width, so nothing beside them shifts. Text, icons, and spacing use fewer sizes, so the same kind of control looks the same on every screen.

Hatoba is now in Scoop's Extras bucket (`scoop install extras/hatoba`) and in the AUR as `hatoba-bin`, and both follow each stable release.

Older versions don't show remote and SOCKS rules synced from this version, and leave them as they are.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
