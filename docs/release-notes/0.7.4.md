## Lock screen fix for SFTP

While Hatoba was locked with a session still connected, a file dragged onto the window could upload into the folder open in that tab's SFTP panel. Now nothing reaches a server from behind the lock screen: SFTP actions, file drops, and resource usage readings wait until you unlock. Transfers that started before the lock still finish. The security advisory [GHSA-m78h-gpf5-jvcg](https://github.com/scarletkc/Hatoba/security/advisories/GHSA-m78h-gpf5-jvcg) has the details.

This version also updates rustls, the TLS library behind Hatoba's HTTPS connections, and the zip library that reads skill archives, to versions with their latest security fixes. A skill `.zip` with a file larger than the archive claims is now refused as damaged.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
