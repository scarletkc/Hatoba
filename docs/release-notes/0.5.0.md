## Importing from other SSH clients, saved hosts for other programs, and Touch ID

New since 0.4.2:

- **Import from other SSH clients**: the host list's **Import** menu reads the saved sessions of Xshell, FinalShell, MobaXterm, PuTTY, Tabby, and SecureCRT as well as `~/.ssh/config`, from where the client keeps them or from a file or folder you choose, such as a SecureCRT export from another computer. Folders become groups, and jump hosts, proxies, and private keys come along where the client saved them. Saved passwords are not imported. The menu is in the list's header too, so you can import after you have added hosts.
- **Saved hosts for coding agents and scripts**: the `hatoba` command can now list your hosts with `hatoba hosts`, run commands on them with `hatoba exec`, and copy files with `hatoba cp`, so programs such as Claude Code and Codex can work on your hosts. Turn on **Use the hatoba command in terminals** in **Settings → General**, then **Let other programs use saved hosts**, which appears below it and is off by default. Hatoba signs in with the host's saved credentials and sends back only the output or the file, so passwords and keys stay in Hatoba. A host key or password it still needs is asked in the window. **Recent use** lists what they ran until Hatoba locks.
- **Touch ID** (macOS): turn on **Settings → Security → Unlock with Touch ID** to unlock with your fingerprint.
- **Memories for each host**: a memory now applies everywhere, to one host, or to this computer's local terminals, and a conversation sees the global memories and those of the host it is on. The assistant chooses when it saves one. **Settings → AI → Memory** lists memories by where they apply, and **Applies To** moves one. Memories saved before stay global.
- **The agent `ssh` uses** (macOS and Linux): signing in with the agent uses the `IdentityAgent` that `~/.ssh/config` sets for the host, as 1Password's setup does, or the `SSH_AUTH_SOCK` your login shell exports, as Bitwarden's does, also when Hatoba was opened from Finder or a desktop launcher.
- **Smoother motion**: menus, popovers, dialogs, and toasts animate in and out, controls fade between their looks, and new tabs, pages, and panels ease in. With reduced motion on in the system, Hatoba keeps the fades and drops the movement.
- **Model limits from models.dev**: the context window, output limit, and thinking levels of well-known models come from models.dev's data. Hatoba carries a copy and asks models.dev when a provider lists a model the copy doesn't know, so new models fill in without an update. xAI, Mistral, Moonshot AI, and Z.ai models fill in too.

In **Auto**, `rg`, `find`, `tail`, `sort`, `journalctl`, `docker logs`, `kubectl`, and similar tools run without asking only with options known to read, so an option that runs another program or writes a file asks first. When Windows Hello or Touch ID stops working, for example after your fingerprints change, the lock screen says it was turned off instead of reporting a wrong master password.

Update Hatoba on every device that syncs your vault: an older version shows a host's memories as global, and editing one there makes it global.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
