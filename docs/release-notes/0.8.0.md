## Telnet hosts, root access from the command line, and SSH sign-in messages

New since 0.7.6:

- **Telnet hosts**: for switches, routers, and other devices that offer Telnet, **New Host** has a **Protocol** choice of SSH or Telnet. Hatoba types a Telnet host's saved user name and password at the device's login prompts, and leaves either one to you when it's empty. Telnet hosts are on the hosts page with the SSH hosts, marked **Telnet**, in their groups, tags, favorites, and searches, and sync like them. A Telnet tab is a terminal like an SSH tab, without SFTP, resource usage, or port forwarding, and the AI assistant works in it by reading the terminal and typing. The search box connects `telnet host [port]` and `telnet://host[:port]`, and so does the `hatoba` command, which also opens a saved Telnet host by its name. Telnet isn't encrypted: the password and everything in the terminal travel as plain text.
- **Root access from the command line**: `hatoba exec --sudo` runs a command as root, and `hatoba cp --sudo` reads or writes a file as root, such as one under `/etc`. `hatoba exec` gives a command no terminal, so a `sudo` inside the command fails as soon as sudo wants a password. When sudo asks for one, Hatoba tries the password you entered for the host in the last 15 minutes, then the host's saved password, and then asks in its window; with `--no-prompt` it fails instead of asking. sudo has to let the login user run `sh` as root. A file uploaded over an existing one keeps its owner and permissions.
- **SSH sign-in messages**: a terminal tab shows the messages a server sends while you sign in, as `ssh` does. When the server holds the login after one, as Tailscale SSH does in check mode with a link to sign in at, a dialog shows the message with **Open Link**, and Hatoba waits for the server instead of giving up after 15 seconds. **Cancel** or closing the tab stops the login. `hatoba exec` and `hatoba cp` print the messages and wait too.

Resource usage keeps being read while the window is minimized or in the tray, so the numbers are current when you come back. Clicking a tab puts the focus in its terminal, also when the tab was already selected or you dragged it, and with the focus on a tab, Left and Right select the tab beside it. A tab's focus ring is no longer cut off at the top and bottom. This version also updates russh, the library behind Hatoba's SSH connections, to a version with its latest security fixes.

The `hatoba-cli` skill now tells coding agents about `--sudo` and about servers that hold the login: run the command under **Skill for coding agents** in **Settings → General** again to update it.

Older versions don't show Telnet hosts synced from this version, and leave them as they are.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
