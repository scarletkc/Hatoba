## Skill for coding agents

The `hatoba-cli` skill teaches Claude Code, Codex, and other coding agents to work on the hosts saved in Hatoba with the `hatoba` command, instead of trying `ssh`, which doesn't know them. While **Settings → General → Let other programs use saved hosts** is on, **Skill for coding agents** below it gives the command that installs the skill, with **Copy Command**. `hatoba --help` also says more about how the commands behave, such as what `hatoba cp` does with a file already at the target and when `hatoba exec` exits with 255.

In Git Bash on Windows, `hatoba exec` and `hatoba cp` now get their arguments as typed: a remote path such as `/var/log` no longer turns into `C:/Program Files/Git/var/log` on its way to the host. Claude Code runs its commands in Git Bash on Windows, so this went wrong in most of its `hatoba exec` calls with a path. Local paths in Git Bash's own form, such as `/c/Users/you/notes.txt`, still work in `hatoba cp`. The `hatoba` command gets the fix the first time Hatoba starts after the update.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
