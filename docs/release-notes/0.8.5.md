## Fewer approval cards in Auto, and host memories for other agents

In **Auto**, a command or file change that changes something, deletes data or sends data elsewhere now runs without asking when you asked for that change. Until now almost every such call asked, also when it was exactly what you asked for. A call still asks whatever you asked for when it touches passwords or keys, weakens security, or runs code that wasn't on the host before and that the judge can't read in full, such as a script piped from the internet into a shell. Packages and images that a package manager or container tool gets from its configured sources don't count as such code. File edits are now checked for weakening security too, so an edit that turns off a certificate check or opens a login to root asks, as the same change made with a command already did. To tell what you asked for, the judge now reads the assistant's replies and the results of its recent calls along with your messages, so these go to the judge's provider too, also when it is another provider than the conversation's.

In **Manual approval**, a `printf` that can set a shell variable, such as `printf -v PATH …`, now asks instead of running as a command that only reads.

The `hatoba` command can now read and save the memories Hatoba's assistant keeps, so coding agents and scripts that work on your hosts through it start from what the assistant already knows about each host. `hatoba memory --host <host>` lists the global memories and that host's, `hatoba memory save` saves one, and `hatoba memory delete` deletes one. A memory saved this way syncs and shows in **Settings → AI → Memory**, and the commands fail while memory is off. On macOS, if **Use the hatoba command in terminals** in **Settings → General** is on, turn it off and on once so that the command in your terminals runs `hatoba memory`. From then on, commands that later versions add work without this step.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
