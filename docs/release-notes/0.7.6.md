## Sync Worker fix for password changes

Changing the master password signs every other device out of sync, so whoever knew the old password loses access. A sign-in with the old password that was already under way when the change went through could still get a session that the change missed. Sync Worker 0.1.2 checks the password again as it creates the session, so that sign-in now fails, and a device whose session another password change has just revoked can no longer change the password either. The security advisory [GHSA-68v5-9v78-32r2](https://github.com/scarletkc/Hatoba/security/advisories/GHSA-68v5-9v78-32r2) has the details.

To get the fix, update your Worker: after Hatoba updates, the sync status page shows **Worker update available**. Choose **Update Worker** and give it a Cloudflare API token with the same permissions as for the first deployment. Sync keeps working until you do.

The AI assistant also waits for a command's output with `read_terminal` instead of running `sleep`, keeps showing its progress updates after a conversation moves between a WSL and a PowerShell tab, and knows which shell it is in after that move.

Installed versions update to this version from **Settings → About**.
