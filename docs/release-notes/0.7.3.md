## Editing remote files in a local editor

**Edit** in a file's menu in the SFTP panel opens the file in an editor on this computer, and each save uploads over the tab's connection. **Settings → Terminal → SFTP → Editor** chooses the editor on each device: **System Default** opens a file with the app the system opens that kind of file with, and **Choose a Program…** picks one. Scripts, programs, and web pages, such as `.sh`, `.py`, and `.html` files, always open in the text editor, so that editing one never runs it.

The file keeps the owner, group, and permissions it has on the server, so a script keeps its execute bit, and editing a symlink writes the file it points to. When the file changed on the server since Hatoba last downloaded or uploaded it, the save asks first: **Overwrite** or **Discard My Changes**. **Editing**, above the transfers, lists the tab's files and the state of their last save. Saves made while the tab is disconnected upload once it reconnects. Nothing uploads while Hatoba is locked, and after the unlock it asks about the saves that haven't uploaded. Stopping an edit, closing the tab, or quitting asks the same before the copy is deleted.

When an MCP server is switched on or off during a conversation, the conversation shows "MCP: … now available" or "MCP: … no longer available", and the assistant no longer takes its earlier replies about that server's tools for mistakes. Asked which MCP servers it has, it no longer says its MCP tools are missing.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
