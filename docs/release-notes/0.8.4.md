## Command suggestions in the terminal

As you type a command at a shell prompt, the rest of the newest matching command you ran there shows dimmed after the cursor, as in fish or PowerShell. This works in SSH, local and Telnet tabs, with nothing to install on the server. → or End takes the whole command, and Ctrl+→ (⌥→ on macOS) its next word. Ctrl+Shift+Space (⌘⇧Space on macOS) opens a list to search, where Enter puts a command in place of what you typed without running it and Shift+Delete removes one. Nothing shows in a full-screen program such as vim, or where the shell already draws its own suggestion.

Hatoba keeps the history of each saved host and each local shell on this device, encrypted with the vault, and doesn't sync it. It reads a command from the screen when you press Enter at a prompt, so a password the shell doesn't show is never kept. A command that starts with a space is left out, as the shells leave it out of their own history.

On an SSH tab, a server you have used without Hatoba suggests what you ran there from the first connection. When Hatoba's history has no match, the suggestion comes from the shell's own history on the server (`~/.bash_history`, `~/.zsh_history` or fish's `fish_history`), and for the first word of a command, from the names of the commands on its `PATH`. A word that starts with `/` or `~/` completes the name of a file or folder through SFTP. The histories and command names are read once when the tab connects and stay in memory for that tab, and nothing on the server changes. A server that refuses, or whose identification names FreeBSD, NetBSD or Windows, leaves the tab with Hatoba's own history.

In **Settings → Terminal**, the **Suggest commands** switch, on by default, controls the dimmed command, and **Clear Command History** deletes the history of every host and shell on this device.

Installed versions update to this version from **Settings → About**. The sync Worker hasn't changed, so there is nothing to redeploy.
