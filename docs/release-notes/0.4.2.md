## Hatoba 0.4.2 — upstream 0.4.1 plus the two open features

This is this fork's build of upstream **0.4.1** — terminal colour presets, notes remembered across
conversations, the document language and the site's in-browser demo among its changes — plus the two
features that are still open upstream.

**Bitwarden's SSH agent** (scarletkc/Hatoba#205). Hatoba finds the agent of this device itself: the
socket you name in Settings → SSH Agent, then `SSH_AUTH_SOCK`, then a known one (Bitwarden, 1Password,
GnuPG, GNOME keyring), so an unlocked Bitwarden vault can hold your SSH keys with no environment
variable to set. On Windows it is the OpenSSH agent or Bitwarden's named pipe.

**Unlock with Touch ID on macOS** (scarletkc/Hatoba#217). Settings → Security offers it on a Mac with
Touch ID: the master password once, then the system's own sheet, and the lock screen then asks for a
fingerprint on its own once per lock. The key stays in the Secure Enclave, and the record beside
`vault.db` (mode 0600) is worth nothing on another Mac. A Mac whose lid is closed cannot read a
fingerprint, and the app says so rather than reporting a cancellation. This part is still being
revised under review in scarletkc/Hatoba#217, so treat it as a preview.

The macOS build is ad-hoc signed and not notarized, as upstream's own is, so the first open needs
**Open Anyway** under **System Settings → Privacy & Security**. Installed builds of this fork update
themselves from this repository.
